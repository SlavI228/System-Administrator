Project 1 — SysAdmin Lab Foundations

Project Overview

The purpose of this project was to build a basic systems administration laboratory from scratch. The lab provides a safe environment for learning Windows and Linux administration, networking, users and permissions, system management, troubleshooting, and documentation.

This project establishes the foundation required for the remaining SysAdmin projects.

Project Goals

The primary goals were:

Build a virtualized laboratory environment. Install and configure operating systems. Configure basic networking. Create and manage users. Configure file permissions. Install and manage software. Manage system services. Practice Windows and Linux administration. Perform basic troubleshooting. Document the environment.

User Management

A basic user-management structure was created.

Example:

Users ├── administrator ├── helpdesk ├── developer └── user01

Users were assigned appropriate permissions based on their intended responsibilities.

The project introduced the principle of least privilege, where users should receive only the access required to perform their jobs.

File Permissions

Linux permissions were tested using:

ls -l

Example:

-rw-r----- user01 employees company.txt

The three primary permission categories were reviewed:

Owner Group Others

And the common permissions:

r = read w = write x = execute

Windows NTFS permissions were also reviewed conceptually.

Troubleshooting Exercise

Problem

A Linux system could not communicate with another machine. Troubleshooting Process

First, the network interface was checked:

· ip addr

Connectivity to the gateway was tested:

ping 192.168.56.118

Troubleshooting Model

Is the interface UP? ↓ Does the virtual machine have an IP? ↓ Is the subnet correct? ↓ Is the gateway reachable? ↓ Is the remote host reachable? ↓ Is the required service running?

This process prevents random changes and helps identify the actual cause.

Security Practices

The following security principles were introduced:

Use strong passwords. Avoid unnecessary administrator privileges. Keep operating systems updated. Disable unnecessary services. Use firewalls. Use SSH securely. Separate administrative accounts from normal accounts. Keep backups of important configuration. Avoid exposing laboratory services directly to the Internet.

Problems Encountered

Problem 1 — Limited Hardware Resources

The lab environment was constrained by available RAM and storage.

#Solution

Only the required virtual machines were powered on at the same time, and unnecessary virtual hardware was minimized.

Problem 2 — Network Connectivity

Connectivity problems were investigated by checking:

IP address Gateway Routing DNS Firewall Services

Problem 3 — Permission Errors

Permission problems were investigated by checking the user identity, group membership, ownership, and permissions.

Lessons Learned

The most important lesson I learned from Project 1 was that systems administration requires understanding how multiple components interact.

For example:

User ↓ Operating System ↓ Network ↓ DNS ↓ Service ↓ Application

A failure at any layer can appear to the user as simply “the system doesn’t work.”

Systematic troubleshooting is therefore more effective than making random configuration changes.
